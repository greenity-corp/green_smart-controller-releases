Controller는 그린스마트 플랫폼에서 **IoT·PLC에 연결되는 손발과 눈**입니다. 장치의 관측·상태를 Edge에 전달하고, Edge가 판단한 요청도 Controller의 현재 대상·기한·중복·허용 범위·안전 조건을 검사한 뒤 실행합니다. 실제 I/O와 장치 결과 확인은 Controller가, 환경 업무 판단은 Edge가 담당합니다.

## 1. 이 저장소와 현재 상태

이 저장소에는 승인된 **Controller 공개 안내·변경 내역·지원 조합·Controller 전용 산출물**을 게시합니다. 제품 소스와 상세 명세는 접근을 제한한 `greenity-corp/green_smart`에서 관리합니다. Cloud·Edge 설치 파일은 각각 전용 채널을 이용하며 이 공개 저장소에 현장 장치 구성·인증정보·고객 데이터를 보관하지 않습니다.

2026-10-20 12:54 KST GitHub Releases API 확인 결과, 이 채널의 반환 목록은 비어 있었습니다. 해당 시각의 게시 현황이며 기존 설치·운영 상태의 조사 결과가 아닙니다. 현재 이 안내에는 검증된 공개 설치 파일·설치 명령·장치/profile 지원 목록·버전 조합을 제공하지 않습니다. 최신 게시 여부는 위 릴리즈 목록에서 확인하세요.

새 기준 문서는 Controller 기능·정비 화면을 구현하고 검사하기 위한 계획입니다. 새 정비 앱·실제 PLC/IoT 연결·물리 쓰기·현장 업데이트 검증의 완료를 뜻하지 않습니다. UI 템플릿/컴포넌트 레퍼런스 비교·선정 이후 최소 구현과 가상/실제 환경 검사를 단계별로 진행하고, 실제 연결·게시·현장 적용은 해당 조건·검토·승인을 따릅니다.

## 2. 정비 사용자 흐름과 실행 책임

| 주요 흐름 | Controller가 맡을 내용 | 판단 시 주의할 구분 |
| --- | --- | --- |
| 접속 대상·정비 범위 확인 | 현재 장치/profile·연결 상태·허용된 정비 주체/기간·Edge 관계 확인 | 화면에 장치가 보이는 것과 제어/정비 허용은 다름 |
| 관측·통신 상태 확인 | 장치 관측·수신 시각/품질·오류·연결 상태를 Edge에 전달하고 허용된 정비 화면에 표시 | 미관측·오래된 값·통신 실패를 실제 정상/0으로 대체하지 않음 |
| Edge 요청 수신·검사 | 대상/profile·기한·중복·현재 허용·인터록을 검사하고 내구 기록과 실행을 연결 | 통신 수신·실행 허용·장치 쓰기·readback·업무 완료는 서로 다른 단계 |
| 결과 불명·원장 대조 | 동일 작업의 기존 실행/관측 기록과 현재 장치 상태를 확인 | 응답이 없다고 새 요청으로 반복 실행하지 않음 |
| 저장·전달·단절 확인 | 내구 원장/버퍼·Edge 전달·ACK와 재연결 상태를 구분 | 메시지 수신/브로커 ACK가 Edge DB의 내구 저장 확인을 대신하지 않음 |
| 업데이트·진단·인계 | 실제 자산/profile·대상·안전 조건·검사/실패/복원 근거를 남겨 지원 | 정비 앱을 새 상시 제어 주체나 Cloud 직접 I/O 경로로 만들지 않음 |

장치 I/O master는 Controller입니다. Edge·Cloud·정비 클라이언트가 별도 경로로 같은 PLC/IoT를 동시에 조작하는 것을 기본 구조로 두지 않습니다. 장치 쓰기 성공 또는 readback 일치도 농장 업무 전체의 완료를 자동으로 뜻하지 않으며 Edge가 해당 업무 결과와 연결합니다.

## 3. 장치 실행부·정비 클라이언트·Core

| 구분 | 목적·대상 | 릴리즈에서 따로 확인할 것 |
| --- | --- | --- |
| Controller 장치 실행부 | IoT/PLC 연결·관측·허용 I/O·안전 검사·원장/버퍼·Edge 교환 | 실제 장치 모델/profile·통신 어댑터·OS/CPU, Edge/계약 호환, 상태/설치·업데이트·복구 검사 |
| Controller 정비 클라이언트 | 기존 실행부에 접속하는 설치·유지보수 담당자의 데스크톱·후속 모바일 앱 | 실제 제공 OS/CPU·접속/권한·정비 범위, Core 소비 버전, 단절/재개·종료·파일/진단 취급 |
| Core 소비 자산 | 공통 규격·오류/상태 의미·구동/교환 지원·정비 UI/템플릿 | 실제 포함 버전·소비 조건. 새 중앙 Core 서버나 별도 장치 펌웨어가 있다고 가정하지 않음 |

장치 실행부는 유지하며, 클라이언트는 공통 기반 언어의 원본에서 **Windows·Linux를 우선 개발**, Android·iOS·macOS는 후속 개발합니다. 클라이언트 대상 OS와 Controller 하드웨어의 실행 환경은 별개의 지원 조건입니다. 구체 프레임워크·UI 라이브러리·최소 OS/CPU·Linux 배포판·패키징·장치/profile은 선정과 해당 환경의 검사 후 안내합니다.

정비 클라이언트의 종료·휴면을 Controller 실행부 종료나 장치 정지로 취급하지 않습니다. 모바일 앱에서 PLC·IoT를 직접 연결해 계속 구동하는 구조를 기본으로 정한 것도 아닙니다. 기존 설치본의 내부 식별·경로는 표시 이름이나 README를 바꿨다는 이유로 변경하지 않습니다.

## 4. 릴리즈 확인·설치·업데이트 순서

1. Controller 릴리즈에서 정식/사전 배포·철회/지원 상태, 공개 변경·제한을 확인하고 장치 실행부와 정비 클라이언트 자산을 구분합니다.
2. 현재 Controller의 실제 자산·장치 모델/profile·통신 어댑터, Edge·Cloud와 클라이언트·Core 소비 버전/계약을 지원 조합과 비교합니다. 모델 이름·버전 숫자가 비슷하다는 이유로 호환된다고 판단하지 않습니다.
3. 실제 대상·장치 상태·정비 권한/기간·Edge의 미완료 작업·내구 원장·버퍼와 복원 조건을 확인합니다. 안전 인터록·설비 운전 상태는 현장 담당자와 대상별로 확인합니다.
4. 승인된 안내의 해당 자산을 내려받아 정확한 파일/번들 식별과 체크섬·서명·신뢰 가능한 발행자/출처를 검증합니다. 미게시 주소·키·명령·장치 연결 순서를 임의로 추측하지 않습니다.
5. 정해진 적용·중단 조건을 따릅니다. 설치/기동, 실제 버전/profile, Edge 관계·허용, 관측, 내구 기록·전달, 허용된 장치 확인을 각각 검증합니다. 실제 물리 쓰기 시험은 해당 대상의 안전 조건과 승인된 시험 범위 안에서 수행합니다.
6. 정비 클라이언트는 실제 대상 OS에서 접속·권한 거절·단절/재개·종료도 확인합니다. 설치·관측·쓰기/readback·Edge 업무 결과와 미실행 범위를 따로 기록하고 인계합니다.

릴리즈에는 공개 허용 source 식별·실행부/클라이언트·Core 소비 버전, 대상 장치/profile·계약·지원/미검증 조합, 자산별 신뢰 검증과 설치·중단·복구·설치 후 확인을 안내합니다. 체크섬만으로 발행자 신뢰를 대신하지 않습니다. ## 6. 공개 범위·농장 정보·지원

장치 실행부와 정비 클라이언트도 **자기 허용 농장/대상 정보와 공유 허용 공용 정보만** 취급하는 방향입니다. 같은 장치 종류·Core UI·공통 프로필 코드를 사용하더라도 다른 농장의 장치 명단·관측·설정·인증정보가 공유되는 것은 아닙니다. 이 문서의 기준과 실제 격리·권한 시험 완료를 구분합니다.

공개 채널에는 승인된 일반 안내·릴리즈 설명·허용 산출물만 게시합니다. 비공개 기준 문서 원문·내부 PR/CI 로그·고객/농장/장치 식별정보·장치 주소·profile의 현장 비밀·설정/원문 로그·자격정보·인증서 개인키·서명키와 미검증 바이너리/임의 체크섬은 게시하지 않습니다.

지원 시 공개 가능한 실행부/클라이언트 버전·OS·일반 장치 유형·발생 시각·민감정보를 제거한 증상·기존 요청의 확인 상태·수행한 조치를 준비합니다. 지정된 비공개 지원 창구가 있으면 그 경로로 전달하고, 공개 이슈에 원문 로그·현장 연결 정보·전체 장치 목록을 붙이지 않습니다. 현재 미정인 지원 장치·응답 시간·공개 연락처를 임의로 안내하지 않습니다.

## 7. 유지관리

새 장치/profile·작업·정비 화면은 해당 계약·중복/만료/결과 불명·실패/복구 검사와 사용자 경로의 E2E에 연결합니다. Edge와의 이전/새 버전 혼용·공통 Core 영향은 실제로 실행한 조합만 근거로 남기며, 생략·미실행을 통과로 채우지 않습니다. 공개 안내와 릴리즈·Cloud의 허용된 현장 버전/지원 정보는 동일한 자산·지원 상태를 가리키도록 갱신합니다.

현장 피드백에는 안전 조건·재현/진단·복구 결과·남은 제한·다음에 재사용할 검사를 기록합니다. 이 README 갱신은 장치 연결·물리 쓰기·자동 업데이트·공개 출고·현장 배포 실행이 아니며 실제 게시·설치/운영 적용은 별도 검토·승인을 거칩니다.
